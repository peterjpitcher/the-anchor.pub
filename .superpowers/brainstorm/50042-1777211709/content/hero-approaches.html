Three approaches to hero consistency

Each solves clutter + conversion differently. Which direction feels right?

A

Strict Template — One Layout, Every Page

Every hero gets exactly: title + one-line description + ONE primary CTA + ONE secondary CTA. No tags, no pills, no secondary info. The image does the selling. Consistency is the feature.

Pros

  • Dead simple, zero clutter
  • Forces you to pick THE action per page
  • Fast to scan — visitors know what to do instantly

Cons

  • Loses context pills (free parking, Heathrow proximity)
  • Some pages genuinely need more info up front
  • May feel too minimal for a pub with personality
B

Tiered Template — 3 Fixed Tiers Based on Page Intent

Define 3 hero "weights" with strict rules about what each can contain:

  • Minimal (landing pages, SEO pages): Title + description + 1 CTA
  • Standard (main sections like /whats-on, /food-menu): Title + description + 1 primary CTA + 1 secondary CTA + up to 3 trust signals
  • Feature (homepage only): Full treatment with seasonal images, multiple CTAs, trust bar

Pros

  • Consistent within each tier
  • Right amount of info for each page type
  • Clear rules — no guesswork about what to include

Cons

  • Need to categorise every page
  • Edge cases ("is this page standard or minimal?")
C

Smart Hero — Dynamic Content Based on Context

The hero adapts automatically: if there's an event tonight, show it. If kitchen is open, show "Order food". If it's Sunday, push Sunday lunch. Time-of-day and day-of-week aware CTAs pulled from the live API data.

Pros

  • Always relevant — the right message at the right time
  • Feels alive and current
  • Could significantly boost conversion with contextual CTAs

Cons

  • Most complex to build
  • Harder to predict what visitors see
  • Risk of confusing messaging if logic gets it wrong
