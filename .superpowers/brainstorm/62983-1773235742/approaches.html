Three approaches to inline PayPal checkout

All three keep the customer on the-anchor.pub. Pick the one that feels right.

A

PayPal Smart Buttons — inline, no redirect

The wizard gains a step 4 "Review & Pay". When the customer clicks the PayPal button, a mini PayPal overlay opens on the page — they pay (PayPal account or card), close the overlay, and land on a branded confirmation page on the-anchor.pub. They never leave the site.

Pros

  • Customer never leaves the-anchor.pub
  • Supports PayPal account and card — no PayPal account needed
  • Booking + payment happen in one atomic flow
  • Reuses existing PayPal backend in management tools
  • Highest conversion — no escape routes

Cons

  • Requires PayPal JS SDK integration on the website
  • Need a new /api/parking/payment/capture route on the website
  • Need a new confirmation page on the-anchor.pub

My recommendation. Most work but solves the problem completely.

B

PayPal redirect — but return to the-anchor.pub

Keep the current redirect-to-PayPal flow, but change the return_url so PayPal sends the customer back to a confirmation page on the-anchor.pub instead of management.orangejelly.co.uk. Minimal backend change.

Pros

  • Very little backend change — just swap return URLs
  • Familiar PayPal flow customers know

Cons

  • Customer still leaves the-anchor.pub to pay
  • Same drop-off risk — people close the PayPal tab
  • Doesn't fully solve the problem

Quick win but doesn't address the root cause.

C

Require payment before booking is submitted

Flip the flow: collect card/PayPal details in the wizard before creating a booking. The booking is only created once payment is authorised. Customer sees booking confirmation immediately after.

Pros

  • Zero pending-unpaid bookings — every booking is pre-paid
  • No capacity held by abandoned checkouts

Cons

  • Biggest backend change — requires PayPal "authorise then capture" pattern
  • More complex error handling if booking creation fails after payment
  • Staff manual bookings would need a different code path

Cleanest data model but highest complexity.
