Behind the scenes
On PayPal button click
Website calls management API: create booking (pending) + PayPal order atomically. Returns paypal_order_id. No SMS sent yet.
On payment approved
PayPal SDK fires onApprove. Website calls management API: capture payment, confirm booking, send confirmation SMS.
PayPal webhook (belt & braces)
Management tools still receive PAYMENT.CAPTURE.COMPLETED webhook — idempotent so it won't double-confirm. Safety net if onApprove fails mid-network.
Staff bookings — unchanged
Management tools flow stays exactly as-is. Staff create booking → payment request SMS sent as today.
Edge cases handled
❌ User cancels PayPal overlay → returns to step 4, can try again. Booking expires in 30 mins (not 7 days).
❌ Capture fails → show error, offer retry or phone number.
❌ Network drops after approval → webhook catches it, SMS still sent.
❌ Slot fills up → capacity re-checked on order creation, not just step 1.
