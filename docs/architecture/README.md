## Key Insights

### API-First Design
The website has **no direct database connection**. All data (hours, bookings, events, reviews) comes from the management API. This is intentional:
- Decouples website from business logic
- Makes it easy to run multiple client apps (admin panel, mobile, etc.) against the same backend
- Allows the website to be deployed independently from database changes

### No Server Actions
Unlike most Next.js apps, this project uses **HTTP API routes, not Server Actions**. Benefits:
- Explicit auth validation visible in each route
- Easy to audit and understand
- Can implement complex caching & middleware strategies
- Works well with the multi-API design

### Hours Logic is Critical
The special_hours override system from the management API is complex:
- `kitchen: null` must be treated as "closed" (use `??` not `||`)
- Sunday lunch has unique rules (walk-ins only, no pre-order)
- Booking availability depends on accurate hours parsing
- See `lib/hours-utils.ts` for correct implementations

### Redirect Flattening
The middleware flattens apex domain + content redirects into single 301 hops to avoid Google Search Console "Redirect error" reports. This is critical for SEO.
