# Data Model

> Auto-generated by session-setup. Manual edits will be overwritten on next refresh.

## No Database in This Project

This project has no database. All data is consumed via API proxy from the management app (`management.orangejelly.co.uk`), which owns the Supabase PostgreSQL database.

## API Client Architecture

The API client lives in `lib/api/` and is organised into domain modules:

| Module | File | Purpose |
|--------|------|---------|
| Client | `lib/api/client.ts` | `AnchorAPI` class -- base HTTP client with API key auth |
| Shared | `lib/api/shared.ts` | Shared types and utilities |
| Bookings | `lib/api/bookings.ts` | Table booking types and methods |
| Events | `lib/api/events.ts` | Event listing, detail, and availability |
| Hours | `lib/api/hours.ts` | Business hours and special hours |
| Menu | `lib/api/menu.ts` | Food and drink menus |
| Parking | `lib/api/parking.ts` | Parking availability, rates, and bookings |
| Private Bookings | `lib/api/private-bookings.ts` | Private hire enquiry types |
| Catering Packages | `lib/api/catering-packages.ts` | Catering package data |
| Index | `lib/api/index.ts` | Barrel re-export |

The singleton API client is exported as `anchorAPI` from `lib/api/client.ts`.

## Data Flow

```
Management App (Supabase DB)
        |
        |  REST API
        |  Auth: X-API-Key header
        |  Base: management.orangejelly.co.uk
        v
  lib/api/client.ts (AnchorAPI class)
        |
        |  Called by API route handlers
        v
  app/api/*/route.ts (proxy routes)
        |
        |  JSON responses
        v
  Client components (fetch from /api/*)
```

## Key Data Types

Data types are defined within each `lib/api/*.ts` module. Key types include:

- **BusinessHours** -- Opening hours with special hours overrides
- **TableAvailabilitySlot** -- Bookable time slots
- **Event** -- Event listing with availability, pricing, categories
- **ParkingAvailability** -- Parking slot availability and rates
