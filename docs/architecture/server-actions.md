# Server Actions & API Client

> Auto-generated by session-setup. Manual edits will be overwritten on next refresh.

## Summary

This project has **zero `'use server'` server actions**. All mutations are handled via **Next.js API Route Handlers** (`route.ts` files) which act as proxies to the management API at `management.orangejelly.co.uk`.

This is intentional — the pattern keeps API key handling centralised in route handlers, provides caching control via middleware, and allows the management API to remain the single source of truth for all data writes.

## anchorAPI singleton

The data layer is the `AnchorAPI` class in `lib/api/client.ts`, instantiated as `anchorAPI` and re-exported from `lib/api/index.ts` (and the legacy `lib/api.ts` shim).

## Mutation pattern

```
Client component
  -> fetch('/api/[endpoint]', { method: 'POST', body })
  -> app/api/[endpoint]/route.ts
  -> fetch('https://management.orangejelly.co.uk/api/[endpoint]', {
      headers: { Authorization: `Bearer ${process.env.ANCHOR_API_KEY}` }
    })
  -> Management API (Supabase DB)
```
