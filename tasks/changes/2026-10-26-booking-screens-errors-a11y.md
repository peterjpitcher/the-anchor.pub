# Booking screens: event from the table page, field errors, accessibility and speed, 26 October 2026

Branch `fix/booking-screens-errors-a11y`. Release 22 of the customer bookings review (AMS repo, `docs/reviews/2026-10-24-customer-bookings-review.md`), approved by the owner.

## Commit 1: the event-from-table journey and field errors (BK-099, BK-102)

- [x] BK-099. Choosing a suggested event on /book-table now loads the whole event (`GET /api/events/{id}`, no-store) before its form appears, so the form shows the price and total, asks for a name and answers per ticket on a paid night with questions, and names the button and heading from the booking mode (`getEventBookingActionLabel`) instead of "Reserve event table". A short "Getting the latest details" status shows while it loads. If the event cannot be loaded, the guest gets a link to the event's own page and the phone number, never a form that might say the wrong thing. New `components/features/TableBooking/SuggestedEventBooking.tsx`; tests in `tests/unit/book-table-suggested-event.test.tsx`.
- [x] BK-102. On the live two-screen flow, a refusal on Confirm sits beside its control: first name, email and notes show the message under the box (invalid and described by it), the policy tick gets its own message linked with `aria-describedby`, and focus moves to the first problem and scrolls it into view. Name, email and policy problems are all shown at once. The number check's refusal is announced (`role="alert"`) under the phone box and linked to it. The top alert is kept for failures of the booking itself and now takes focus. `findDetailsStepRefusals` in `lib/table-booking/journey.ts` returns every field refusal with the field it belongs to; tests in `lib/table-booking/__tests__/details-step-refusals.test.ts` and the two-screen suite.
- Left: the old four-step path keeps the top alert. It is deleted in commit 3.

## Commit 2: accessibility (BK-103, BK-104, BK-194 to BK-198, BK-210, BK-222)

- [x] BK-103. New `hooks/useFocusOnChange.ts` moves focus to a new screen's heading (tabIndex -1). Applied to: the details heading after Continue, the times heading after Back or a dropped time, the "Event booking" heading, the "You're all booked in" heading, the quick booking sheet's "You're booked in" and "held, not booked" lines, and the private hire "Enquiry received" heading. After the number check focus goes to First Name for a new guest and Notes for a known one. The number check's answer, the re-check note, a dropped time and the "answer the question above" note now sit in live regions that stay on the page (empty, they take no space).
- [x] BK-104. New `--border-field` token (light `#857b6a`, 4.17:1 on white; dark gold at 0.75, 3.99:1 on the card), Tailwind `border-line-field`, used by `fieldControlClass` and swept onto the booking and enquiry forms' own field classes (private hire quick and full forms, Christmas forms, pre-order selects, the quick booking date box). Event question boxes moved onto `fieldControlClass`. Chosen time, high chair count and Christmas answer use `border-accent bg-accent text-canvas` with a tick. `tests/unit/field-border-contrast.test.tsx` holds both skins to 3:1; the browser audit now measures every visible field's edge (axe does not).
- [x] BK-194. High chairs are native radios in a fieldset with a legend: one Tab stop, arrow keys from the browser. The browser audit presses ArrowRight on them for real.
- [x] BK-195. Quick booking sheet: a status line says how many times are available after every chip; times print as "7pm" in the grid and the summary; on a Sunday the extra chip says "Next Sunday"; both boxes are required and each refusal sits under its own box with focus on the first.
- [x] BK-196. Event booking buttons no longer read the tracking source to screen readers; it stays in the click tracking.
- [x] BK-197. The Christmas pop-up has visible labels, including "Preferred date".
- [x] BK-198. Table, quick booking, private hire and event submit buttons stay focusable while the security check runs (`Button` `unavailable`, aria-disabled) and say "Waiting for the security check." underneath (`SecurityCheckWaitingNote`). The ten-second help panel is unchanged.
- [x] BK-210. `hourCycle: 'h12'` instead of `hour12: true` in the deposit deadline, the event clock time fallback and the quiz terms page. Confirmed on Node 20: the old setting printed "0:15 pm".
- [x] BK-222. The browser audit presses through /book-table with the availability, number check and a fixture prepaid event with questions answered by Playwright (every other write to the site's API is refused in the browser): times, details, Confirm with empty fields, Back, the event form and its own refusals, checking focus and running axe at each step. The dated quiz night row is gone; the event template is checked on the next event on sale, found at run time.
- Left: the Christmas forms' own submit buttons and the event waitlist button keep the native disabled state (not named in BK-198). The recruitment form, the private hire cost estimator and the Nations Championship filter selects keep their old field borders (not booking or enquiry forms).

## Commit 3: speed (BK-199, BK-200)

- [x] BK-199. The quick booking sheet is fetched with `next/dynamic` when the booking bar first comes on screen and mounted closed, so the first tap still slides it open; pages where the bar never shows (/book-table) never load it. `PayPalDepositSection` and `PayPalEventPaymentSection` are fetched only when a payment is due. The Christmas drawer starts its security check only once the drawer has been opened. The four-step booking journey is deleted (website W4): its JSX, handlers and state, the `booking_options_step1` flag read, `lib/table-booking-slot-window.ts`, the `hideWhenNoHighChairFree` fork (now always on, owner decision D4) and the unused `coversHighChairRequest`. `ManagementTableBookingForm.tsx` is 3,889 lines down to about 3,200. Its 4,080-line suite was rewritten for the two-screen journey: tests that described only the old path (seven-slot window, Preferred Time, review screen, details-step chair stepper) were dropped where the two-screen suite already covers the behaviour, and the rest were ported. Build check: PayPal's wrapper and the quick booking sheet are no longer in the first-load chunks of /book-table, the event pages, /sunday-roast or /christmas-parties.
- [x] BK-200. /book-table reads nothing from the request: the form reads the date, time, party size, drinks choice and a Nations Championship game from the address in the browser (`lib/table-booking/prefill.ts`), inside a Suspense boundary with a fallback that holds its place, and looks the game up from `/api/nations-championship` itself. `lib/flags.ts` caches its read for 60 seconds (`next: { revalidate: 60 }`) instead of `no-store`. The hours box stays on the cached snapshot. `next build` now lists `/book-table` as static (it was rendered on demand), and a local `next start` answers it with `x-nextjs-cache: HIT`.
- Left: `lib/flags.ts` now has no callers on the site; it is kept, cached, for the next flag. The production `x-vercel-cache` check needs the deploy.
