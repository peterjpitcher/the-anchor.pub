**Findings**
1. High: the patch does not actually guarantee “render with noindex” for stale/no-next-event pages, because the only runtime consumer ignores `seoStrategy.index` entirely. [lib/event-seo-strategy.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-seo-strategy.ts:72) now returns `{ index: false }`, but [app/events/[id]/page.tsx](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:255>) only checks `seoStrategy.redirect`. `robots` is recomputed separately in [generateMetadata()](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:170>) and uses `>` while the strategy uses `<`, so the exact boundary days disagree. At exactly 30 days, the strategy says “stale/noindex” but metadata still leaves the page indexable; same bug at exactly 7 days for cancelled events. [app/sitemap.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/sitemap.ts:238) has the same `>` drift, so sitemap and page behavior diverge too.

2. High: “no next upcoming event in category” is not a trustworthy condition. The lookup in [app/events/[id]/page.tsx](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:245>) calls `getUpcomingEventsByCategory()`, but that helper only requests `status: 'scheduled'` in [lib/api/events.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/api/events.ts:586). Future `rescheduled`, `postponed`, and `sold_out` events are treated as real event states elsewhere in [lib/event-lifecycle.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-lifecycle.ts:18) and included in the sitemap status filter in [app/sitemap.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/sitemap.ts:14), but this lookup ignores them. After this patch, that blind spot no longer falls back to a category redirect; it now lands on the new no-redirect stale page path.

3. Medium: there is a repo-level timezone contradiction that is a more plausible root cause than the redirect policy. `isEventInPast()` in [lib/event-lifecycle.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-lifecycle.ts:38) uses `Date.parse(event.startDate)` as an absolute instant, but `formatEventTime()` in [lib/api/events.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/api/events.ts:375) explicitly says the API’s offset should be ignored because the numeric time is meant to be UK local time. Those two assumptions cannot both be right. I verified locally that `isEventInPast('2025-07-18T19:00+00:00')` is still `false` at `2025-07-18 19:30 BST`, even though the display layer would show that event as a 7:00pm local start. That means stale/noindex/redirect transitions can lag by an hour during BST.

4. Medium: cancelled events still trigger a same-category lookup they can never use, and the page comment is false. [app/events/[id]/page.tsx](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:241>) says “redirect stale past/cancelled events”, then always does the next-event lookup for cancelled items. But the cancelled branch in [lib/event-seo-strategy.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-seo-strategy.ts:50) never returns a `redirect`. So every cancelled event page pays for an unnecessary API call and the comment documents behavior that does not exist.

5. Low: there is dead contract surface left behind. After this change, `event.category` in the `getEventSeoStrategy()` input type is unused in [lib/event-seo-strategy.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-seo-strategy.ts:43). Also, `showEndedBanner` and `stage` are unused anywhere in the repo. `CATEGORY_ROUTES` is not dead, though; `getCategoryPageUrl()` is still used by breadcrumbs and the category CTA in [app/events/[id]/page.tsx](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:391>) and [app/events/[id]/page.tsx](</Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx:623>).
