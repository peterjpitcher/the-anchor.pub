## Finding AB-001: `/events` Is Not a Safe Universal Fallback
**Type:** Strongly suspected
**Severity:** High
**Description:** The spec treats `/events` as an acceptable generic fallback when `slug`, `id`, and `event.url` cannot produce a valid event-page URL. That is only defensible for generic navigation. It is not safe for identity-bearing outputs like sitemap entries, Schema.org `@id`/`url`, share URLs, Google Calendar links, or ICS `URL:` fields. Multiple malformed events would collapse onto the same `/events` URL and no longer have distinct canonical identities.
**Evidence:** The current helper falls back to `EVENT_PATH_PREFIX` (`/events`) in [lib/event-url.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-url.ts:46). The spec preserves that behavior and calls it “acceptable generic fallback” at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:101). That fallback feeds [app/sitemap.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/sitemap.ts:253), Schema.org `@id` and `url` in [lib/structured-data/event-schema.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/structured-data/event-schema.ts:50) and [lib/structured-data/event-schema.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/structured-data/event-schema.ts:121), share URLs in [components/events/EventSecondaryActions.tsx](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/components/events/EventSecondaryActions.tsx:21), and calendar/ICS outputs in [lib/event-calendar.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-calendar.ts:143), [lib/event-calendar.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-calendar.ts:160), and [lib/event-calendar.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-calendar.ts:198).
**Why it may be wrong:** Fixing leakage by collapsing bad events onto the listing page may create duplicate sitemap URLs and repeated Schema.org IDs. That can be worse than a bad category link because it fabricates one shared identity for multiple distinct events.
**What would confirm it:** Create two events with `slug: ''`, `id: ''`, and invalid or external `url` values, then inspect generated sitemap entries and JSON-LD. If both events emit `https://www.the-anchor.pub/events`, the fallback is not safe for those consumers.

## Finding AB-002: The Allowlist Does Not Enforce the Actual Route Contract
**Type:** Strongly suspected
**Severity:** Medium
**Description:** The new guard accepts any path that starts with `/events/`, but the app only exposes a single-segment event route. That means malformed paths like `/events/foo/bar` or `/events/foo/` can still pass the allowlist even though they are not guaranteed to resolve to the canonical event page.
**Evidence:** The spec’s acceptance check is `resolved.startsWith('/events/') && resolved.length > '/events/'.length` at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:93). The current resolver returns raw `pathname` strings in [lib/event-url.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-url.ts:15). The repo only defines [app/events/[id]/page.tsx](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/app/events/[id]/page.tsx), not a catch-all route.
**Why it may be wrong:** A prefix check fixes category leakage but still allows invalid internal paths to masquerade as canonical event URLs. If the management API ever returns a nested or slash-suffixed path, the new guard will accept it without normalization.
**What would confirm it:** Add tests for `https://www.the-anchor.pub/events/foo/bar` and `https://www.the-anchor.pub/events/foo/`, then decide whether the intended behavior is rejection, normalization to `/events/foo`, or pass-through.

## Finding AB-003: The Schema Layer Reintroduces a Brittle Blocklist
**Type:** Strongly suspected
**Severity:** High
**Description:** The spec correctly moves `event-url.ts` away from `CATEGORY_ROUTES`, but `event-schema.ts` still plans to sanitize with a category-page blocklist. That means the future-growth problem survives in structured data: new category aliases, `/whats-on`, `/events`, or other same-origin non-event pages can still leak through some schema fields.
**Evidence:** The planned schema helpers only reject `CATEGORY_PAGE_PATHS` at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:125), [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:171), and [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:195). The same spec explicitly identifies `/whats-on` as a bad non-event path in [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:57) and adds a dedicated `getEventWebsitePath()` test for it at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:286), but does not reject `/whats-on` in any schema helper.
**Why it may be wrong:** The design solves “future category growth” in one layer and then quietly reintroduces it in another. `mainEntityOfPage` is especially risky because this JSON-LD is rendered on The Anchor pages; an external or listing-page `@id` is not a trustworthy page identifier there.
**What would confirm it:** Add tests with `mainEntityOfPage['@id']='https://www.the-anchor.pub/whats-on'`, `offers.url='https://www.the-anchor.pub/whats-on'`, and a category alias not present in `CATEGORY_ROUTES`. If those values pass through, the blocklist is still too weak.

## Finding AB-005: The Fix Claims to Address the Broader Class, but Leaves the Lossy Normalizer Intact
**Type:** Spec ambiguity
**Severity:** Low
**Description:** The revised spec correctly identifies `resolvePathFromUrl()` as the broader problem, but the actual design only wraps its output in `getEventWebsitePath()`. The helper itself remains lossy and misleading. That is probably acceptable today because it is private, but it means the bad behavior is masked rather than removed.
**Evidence:** The spec says the fix must address the broader bug at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:12), yet Change 1 only adds a guard after the resolver at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:80). The underlying helper still strips origins and returns raw pathnames in [lib/event-url.ts](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/lib/event-url.ts:13).
**Why it may be wrong:** Future reuse will reintroduce the same bug class, because the unsafe semantics are still embedded in a generic-sounding helper.
**What would confirm it:** Decide whether `resolvePathFromUrl()` should remain as-is, be renamed to reflect its lossy behavior, or absorb the allowlist logic. If the answer is “other callers should never use it raw,” then the current API boundary is misleading.

## Finding AB-006: The Complexity Score Is Still Optimistic
**Type:** Spec ambiguity
**Severity:** Low
**Description:** A `3 (M)` estimate assumes the design is already settled. It is not. The schema URL helper contract is still unresolved, the `/events` fallback risk is not addressed, and the test plan does not yet include the integration surfaces that would actually prove the fix is correct.
**Evidence:** The spec notes its own helper-contract gap at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:163), sets complexity to `3 (M)` at [docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md](/Users/peterpitcher/Cursor/OJ-The-Anchor.pub/docs/superpowers/specs/2026-04-12-category-url-leakage-fix-design.md:318), and the repo still has no dedicated tests for `getEventWebsitePath`, `getEventWebsiteUrl`, or `resolvePathFromUrl`.
