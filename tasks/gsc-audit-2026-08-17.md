The full live check found:

- 275 URLs redirecting. Every redirect reaches a final 200 page.
- 172 URLs returning 404. They are old assets, blocked utility URLs, malformed URLs, or historical pages outside the current sitemap.
- No current sitemap URL returning 404.
- No broken redirect destination.

There are **four real code improvements** worth making:

1. Stop using an event's future date as the sitemap `lastmod` date.
2. Remove incorrect `Product` schema from the fish-and-chips page and use `Service` instead of `Product` for parking.
3. Correct event schema lifecycle and offer data on seasonal and finished event pages.
4. Fix the doubled brand name in the Mother's Day page title.

There are also a few recrawl and internal-link actions. None of these are a critical outage.

## Priority fix list

### P1 — Fix future sitemap `lastmod` dates

**Problem:** Event sitemap entries fall back to the event start date when no real update date exists. Future events can therefore have a future `lastmod` value. For example, the September and December 2026 event URLs currently have future `lastmod` dates.

**Why it matters:** `lastmod` should describe when the page content changed, not when the event happens. Incorrect future dates give Google a weak or misleading crawl signal.

**Fix:** In `app/sitemap.ts`, use only a genuine content update timestamp such as `_meta.lastUpdated`. Omit `lastModified` if no trustworthy update date exists. Do not fall back to `event.startDate`.

**Code:** `app/sitemap.ts`, around line 315.

### P1 — Correct product and merchant schema

#### Fish and chips page

**Problem:** A pub meal is marked as a `Product`. Google therefore treats it like a shipped retail item and reports missing shipping, return-policy, review, and rating data.

**Fix:** Remove the `Product` block. Keep the existing `Menu`, `MenuSection`, and `MenuItem` schema, which correctly describes food sold by a restaurant.

**Code:** `app/fish-and-chips-heathrow/page.tsx`, around lines 67–113.

#### Heathrow parking page

**Problem:** Long-stay parking is marked as a `Product`, which causes product-snippet warnings about reviews and ratings.

**Fix:** Change it to `Service` with an `Offer` or `AggregateOffer`. Keep the existing `ParkingFacility` data.

**Code:** `app/heathrow-parking/page.tsx`, around lines 224–242.

These warnings are not penalties. Both items are currently valid in Search Console, but the schema types are not the best description of what the pub sells.

### P1 — Correct event schema lifecycle and offers

#### Finished World Cup page

**Problem:** The World Cup page says the event ended on 19 July 2026, but its live schema still advertises an `InStock` booking offer.

**Fix:** Remove the live offer after the event ends. Prefer removing the `Event` schema after the campaign has finished and leaving the page as normal historical content.

**Code:** `app/live-sport/world-cup/page.tsx`, around lines 83–126.

#### Easter and Mother's Day pages

**Problem:** Their event offers have no price or currency. Google also asks for a performer, although a performer is not meaningful for a roast or lunch event.

**Fix:**

- If the page advertises a real paid package, add the genuine price, `GBP`, and a truthful `validFrom` date.
- If there is no fixed ticket or package price, remove the `offers` block. Do not invent a zero price.
- Ignore the optional performer warning unless a real performer is booked.

**Code:** `app/easter-sunday/page.tsx` and `app/mothers-day/page.tsx`.

### P2 — Fix the Mother's Day title

**Problem:** The live title is `Mother’s Day Lunch & Sunday Roast Near Staines | The Anchor | The Anchor`.

**Fix:** Remove `| The Anchor` from the page-level title because the root title template already adds it.

**Code:** `app/mothers-day/page.tsx`.

### P2 — Strengthen discovery for useful pages

Google has found but not indexed these seven sitemap URLs:

- `/blog/40th-birthday-party-ideas-venues`
- `/blog/christmas-dinner-or-party-night-which-suits-your-group`
- `/blog/cosy-pub-stanwell`
- `/blog/pub-vs-hotel-celebration-venue`
- `/drinks/baby-guinness`
- `/events/cash-bingo-2026-09-02`
- `/events/nikki-s-karaoke-night-2025-08-22`

The four blog pages contain substantial original content. This is not a thin-content problem. The Christmas article was also only one week old at the time of this audit.

**Actions:**

1. Add one or two natural internal links to `/blog/pub-vs-hotel-celebration-venue` from private-hire and celebration pages. It is the weakest-linked article in this group.
2. Check that the September 2026 cash bingo event appears on the live What's On page.
3. Use URL Inspection to request indexing for the four blog posts, Baby Guinness, and the future cash bingo page.
4. Do not spend time pushing the old August 2025 karaoke page unless it still has business value.

## What each Search Console issue means

### Page with redirect — 144 URLs

**Search Console status:** Validation failed.  
**In the current sitemap:** 12 URLs.

Most of the 144 are old URL forms or expected redirects. All 12 sitemap URLs in this group now return a direct 200 response and are self-canonical. The report is stale for those pages.

**Action:** No redirect code change is currently needed for the 12 sitemap URLs. Request a recrawl and wait for Search Console to update.

### Excluded by `noindex` — 100 URLs

**Search Console status:** Validation failed.  
**In the current sitemap:** 10 URLs.

The full group includes tag archives, retired events, confirmation pages, and other pages that were deliberately excluded. All 10 sitemap URLs currently return `index,follow` and have a self-canonical tag.

**Action:** Keep intentional exclusions as they are. Request a recrawl for the 10 current sitemap pages.

### Blocked by robots.txt — 88 URLs

This group is mainly short-link host URLs, Next.js assets with query strings, calendar API routes, and Cloudflare email-protection URLs. These are not search landing pages.

**Action:** None. They should not be indexed.

### Not found (404) — 20 URLs

**Search Console status:** Validation failed.  
**In the current sitemap:** One URL, `/events/quiz-night-2026-12-02`.

That event page now returns a direct 200 response and is indexable. The remaining 404 group is mostly old hashed CSS files, malformed URLs such as `/5` and `/private-party-`, and an old missing-extension image URL.

**Action:**

- Request indexing for `/events/quiz-night-2026-12-02`.
- Leave meaningless asset and malformed URLs as 404. Do not redirect every 404 to the home page.
- Only add a redirect if a bad URL has real links or traffic and there is a clear equivalent page.

### Alternative page with proper canonical — 11 URLs

These are mainly booking, source, or date parameter URLs. Their canonical behaviour is expected. The old `blog?page=12` record is stale; current blog pagination pages are self-canonical, while page 1 redirects to `/blog`.

**Action:** None, apart from normal monitoring.

## Recommended Search Console process

1. Deploy the code fixes listed above.
2. Inspect and request indexing for the priority URLs below.
3. Resubmit the main sitemap once. Repeated submissions will not speed up crawling.
4. Wait for Google to recrawl. Search Console reports often lag behind the live site.
5. Review sitemap-only indexing weekly for four to six weeks.
6. Do not repeatedly run **Validate fix** on a mixed category containing intentionally blocked, redirected, canonicalised, or missing URLs. It can fail even when the useful sitemap pages are healthy.

## Audit method and limits

This report combines the signed-in Search Console reports, all eight exported issue CSV files, and a live check of all 695 affected URLs. The live check recorded direct HTTP status, redirect destination, robots directives, canonical tags, and sitemap membership. Selected structured data was also checked from the rendered pages.

Search Console is historical and delayed. A URL can be healthy today while still appearing under an old exclusion reason until Google crawls it again.
