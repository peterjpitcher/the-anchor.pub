## Ticket-Ready Fixes

### T1 — Verify the conversion pipeline end-to-end (Tier-1 prerequisite, Do now)
- **Problem:** Every commercial event is correctly wired in code, but nothing downstream of the dataLayer can be verified: no GTM container export, no GA4 property access, GA4 MP env vars unconfirmed since June. A wired container that forwards nothing is a common silent failure.
- **Affected:** all templates; GTM-WWFQTQS; GA4 property (ID unknown to this audit).
- **Events to verify and mark as GA4 key events:** `table_booking_completed`, `purchase`, `event_booking_completed`, `private_hire_enquiry_submitted`, `call_click`.
- **Trigger conditions:** GTM Custom Event triggers matching those exact dataLayer event names.
- **Parameters:** as pushed (see `lib/gtm-events.ts`) — `booking_type`, `party_size`, `booking_date`, `transaction_id`, `value`, `currency`, plus attribution keys (`landing_path`, `utm_*`).
- **Consent dependency:** analytics consent required (dispatcher hard-gate) — test with consent accepted.
- **QA method:** GA4 DebugView + one test booking (drinks type, party of 2), one test private-hire enquiry, one phone-link click.
- **Acceptance criteria:** each event visible in DebugView with parameters; all five marked key events; screenshot archived to the run workspace.
- **Rollback:** none — verification + GA4 admin config only.

### T2 — Set `NEXT_PUBLIC_META_PIXEL_ID` in Vercel and redeploy
- **Problem:** env var absent at build time; pixel code ships but never initialises (bundle proof above).
- **Affected:** entire site; Meta Purchase dedup (`eventID` = booking reference) currently unused.
- **Implementation:** Vercel → Project → Settings → Environment Variables → `NEXT_PUBLIC_META_PIXEL_ID=757659911002159` (production) → redeploy.
- **Consent dependency:** marketing consent (correctly gated in `lib/meta-pixel.ts:47`).
- **Acceptance criteria:** `curl` of new booking-form chunk contains `757659911002159`; Meta Events Manager Test Events shows PageView + Purchase.
- **Rollback:** unset the var and redeploy.

### T3 — Set `GA4_MEASUREMENT_ID` + `GA4_API_SECRET` in Vercel (June open item)
- **Problem:** `/api/analytics` silently no-ops without them; server-side event copies lost.
- **Implementation:** GA4 Admin → Data Streams → Measurement Protocol API secrets → create; add both vars in Vercel; redeploy.
- **Acceptance criteria:** POST a test payload `{"event":"mp_healthcheck"}` to `/api/analytics`, event appears in GA4 Realtime within minutes.
- **Rollback:** unset vars (route degrades gracefully by design).

- **Acceptance criteria:** live HTML contains both keys; Tag Assistant shows all four v2 signals.

- **Events:** `phone_call_click`/`call_click`, `email_click` (existing definitions, no new schema).
- **Acceptance criteria:** greps in the table above return clean; click each replaced link once with DebugView open.
- **Rollback:** revert component swaps.

### T6 — Pass deposit value into the standard booking-success path
- **Problem:** `ManagementTableBookingForm.tsx:1660-1669` omits `value` on `trackTableBookingFunnel({step:'success'})`, so the Meta Purchase (once the pixel is live) reports value 0 even for deposit bookings; the PayPal path (`:2463`) passes it correctly.

- **Acceptance criteria:** test deposit booking emits Meta Purchase with value > 0.
- **Rollback:** revert one-line change.
