# UX & Conversion Analysis — The Anchor (Full Overhaul, 7 July 2026)

Agent: UX/CRO Specialist. Evidence: codebase @ main (19e88215), live fetches of www.the-anchor.pub/private-hire and /sunday-roast (2026-07-07), crawl evidence in `evidence/` (240 pages), strategy doc. **No GA4/GSC/CrUX data this run** — no bounce/conversion/engagement figures are quoted anywhere; behavioural claims are marked inferred. Real bookings/enquiries were NOT submitted — conversion paths were verified by tracing the code wiring end-to-end, as the skill rules require.

---

## Summary

The conversion plumbing is fundamentally sound — this is not a site with dead forms. All four primary conversion paths were traced end-to-end in code and every one reaches a real destination (the management API and/or a Microsoft Graph email). Error states in the table-booking wizard consistently offer a phone fallback, phone CTAs use the correct number (01753 682707) via tracked components, and the global sticky CTA bar is well-built (tracked, aria-labelled, 48px targets).

The problems are second-order but sit exactly on the owner's priority pages:

1. **Money pages display broken prices.** A shared formatter strips the "£" from live menu prices, so /sunday-roast (priority-1) renders "Roasted Turkey16" and meta descriptions say "Dishes from 4." — the site looks broken at the exact moment it should look trustworthy.
2. **The private-hire enquiry (priority-2) is buried behind a cost estimator.** Every "Start your enquiry" CTA lands on a section containing a single "Open Cost Estimator" button; the actual enquiry form is 3+ interactions deep, gated by a phone-verification step, and the whole path dies with no fallback if the estimator config API fails.
3. **The corporate-events hero sends enquirers to the wrong tool** — "Book Your Event" opens the restaurant table wizard (20-cover cap), and the hero phone CTA is untracked.
4. **Measurement of phone conversions is leaky**: 14 raw `tel:` links across 13 pages (including corporate-events) bypass the tracked PhoneButton/PhoneLink components, and the Christmas enquiry's email delivery depends on Microsoft Graph env vars that cannot be verified this run.

## 1. Conversion Path Verification (end-to-end traces — the non-negotiable)

### 1a. Table booking — VERIFIED WIRED ✅
- **Flow**: `/book-table` (`app/book-table/page.tsx:187`) renders `ManagementTableBookingForm` — a 4-step wizard (`find → choose → details → review`, `components/features/TableBooking/ManagementTableBookingForm.tsx:152`).
- **Submit**: POST `/api/table-bookings` with an idempotency key (`ManagementTableBookingForm.tsx:1607`) → proxy validates payload, forwards to `${managementApiBase}/table-bookings` with `ANCHOR_API_KEY` (`app/api/table-bookings/route.ts:391,458`). Confirmed/pending-payment/blocked states all handled; blocked reasons mapped to human copy with phone fallbacks (`ManagementTableBookingForm.tsx:162-167,1635-1649`).
- **Deposits (groups 10+)**: PayPal create/capture routes exist and are called (`/api/table-bookings/paypal/create-order`, `ManagementTableBookingForm.tsx:870`); payment error state offers "call us" recovery (`:2400-2406`).
- **Availability**: `/api/table-bookings/availability` with error fallback copy including the phone number (`:1146`).
- **Tracking**: funnel events (start/step/submit/success/error), GA4 `purchase` dataLayer push with booking reference as `transaction_id` (`:1677-1684`). *Whether these reach GA4 is unverified — the GA4 Measurement Protocol env vars are the Analytics agent's SEO-001 Critical.*
- **Verdict**: the conversion neck of the site is in good shape. No Tier-1 defect here.

### 1b. Private-hire enquiry — WIRED, BUT LONG AND FRAGILE ⚠️
- **Destination trace (works)**: `PrivateBookingInquiryForm` → `createPrivateBooking()` (`lib/api/private-bookings.ts:119`) → browser POSTs `/api/public/private-booking` → proxy forwards to management `/private-booking-enquiry` with `ANCHOR_API_KEY` (`app/api/public/private-booking/route.ts:143`). Missing API key returns a visible 503, upstream errors are surfaced to the user — **not a silent void**. Success fires `trackPrivateHireEnquirySubmitted`.
- **BUT the path to that form is long**: `/private-hire#enquiry` → section shows only an "Open Cost Estimator" button (`components/PrivateBookingSection.tsx:34-39`, confirmed live 2026-07-07) → drawer opens `PrivateBookingCalculator` (date, event type, space, guests, hours, packages, vendors) → "…" button sets `showInquiryForm` (`PrivateBookingCalculator.tsx:791`) → form requires mobile number + "Continue" lookup gate before any other field unlocks (`PrivateBookingInquiryForm.tsx:79,161-163`) → submit. That is ~6–8 interactions and two hard gates between "Start your enquiry" and a sent enquiry.
- **Dead end on error**: if the estimator config fetch fails, the drawer renders only "Unable to load calculator: {error}" (`PrivateBookingCalculator.tsx:202`) — no enquiry form fallback, no phone number anywhere inside the drawer or section (grep: zero `PhoneLink|01753|tel:` in `PrivateBookingCalculator.tsx` / `StickyEstimatorDrawer.tsx`). The page-level phone CTAs mitigate, but the user is inside a drawer at that point.
- **Copy bug**: "Recognized customer" (`PrivateBookingInquiryForm.tsx:~297`) — US spelling; brand is British English.

### 1c. Event bookings (incl. PayPal) — VERIFIED WIRED ✅ with one dead end
- **Flow**: `ManagementEventBookingForm` → POST `/api/event-bookings` (`:444`) → proxy → management `/event-bookings` (`app/api/event-bookings/route.ts:463`); waitlist path to `/api/event-waitlist`; PayPal create/capture present (`PayPalEventPaymentSection.tsx:98,183`).
- **SALES_CLOSED (recent work, checked as briefed)**: handled at page load (`isEventBookingClosed`), at proxy (409 mapped, `app/api/event-bookings/route.ts:492-496`) and at submit-time race (409 → friendly closed panel, no generic error — `ManagementEventBookingForm.tsx:482-486`). Good engineering. **UX gap**: the closed panel says "Please contact us if you need help" with **no contact affordance** — no phone link, no link back to /whats-on (`ManagementEventBookingForm.tsx:701-710`). A ticket-buyer hitting the cutoff is dropped at a literal dead end.

### 1d. Christmas parties enquiry — WIRED, DELIVERY UNVERIFIABLE ⚠️
- **Flow**: modal form (dinner ≤25 / buffet 26+ modes, tracked CTAs) → POST `/api/enquiry/christmas` → sends email via **Microsoft Graph** (`app/api/enquiry/christmas/route.ts:127`) AND creates a management-API booking (`:201`).
- **Risk**: delivery depends on `MICROSOFT_TENANT_ID/CLIENT_ID/CLIENT_SECRET/USER_EMAIL` (documented in `.env.example:47-50`). If unset, users get a visible 500 ("Email service is not configured") — not silent, but a **total conversion failure on the in-window seasonal page** if those vars are missing in Vercel. Cannot verify Vercel env this run. Must be verified alongside SEO-001's GA4 vars — one owner action, two checks.

### 1e. Phone CTAs — CORRECT NUMBER, PARTIALLY UNTRACKED ⚠️
- `PhoneButton`/`PhoneLink` render `tel:+441753682707`, correct number from `lib/constants.ts:3-6`, and fire `trackPhoneCallClick` — used across money pages with per-placement `source` labels. ✅
- **14 raw untracked `tel:` links in 13 files** (`grep Link href={CONTACT.phoneHref}|"tel:+441753682707"`): corporate-events (×2, incl. the hero "Discuss Your Event" CTA) + 12 location pages (ashford-pub, staines-pub, windsor-pub, feltham-pub, egham-pub, bedfont-pub, colnbrook-pub, horton-pub, longford-pub, stanwell-pub, sunbury-pub, wraysbury-pub). They dial fine but never fire `trackPhoneCallClick` → phone conversions systematically undercounted on exactly the local-intent pages where calls are the natural action. (These are server components — that's *why* raw links were used; `PhoneButton` is a client component and can be dropped in directly.)
- Sticky bar phone/WhatsApp icons: aria-labelled, tracked. ✅

## 4. User Journey Mapping & Dead Ends

- **Plane-spotting/Heathrow entry → food conversion**: cross-sell CTAs already present on /plane-spotting-heathrow and /beer-garden (`plane_spotting_roast_cta`, `beer_garden_roast_cta` etc.) — the "protect and convert" pattern the strategy calls for exists. ✅
- **Dead end 1**: SALES_CLOSED panel (§1c) — no next step.
- **Dead end 2**: estimator config failure (§1b) — no next step inside the drawer.
- **Tone gap, wakes**: every occasion page funnels to the same estimator section titled "Instant Quote & Check Availability" / "Get an immediate cost estimate for your gathering" (`PrivateBookingSection.tsx:14-15`). On /private-hire/wakes, asking a bereaved family to "build a bespoke quote… choose extras to see a live price breakdown" is the wrong register; the page's phone-first hero is right, but the on-page form path should say something like "Tell us what you need and we'll take care of it". One prop already exists (`title`/`subtitle`) — this is a copy-level fix per occasion.
- **Sticky CTA context mismatch (Medium, inferred)**: the single global sticky bar always pushes "Book a table" + menu, even on /private-hire, /christmas-parties, /corporate-events where the conversion is an enquiry (`components/layout/StickyCtas.tsx:138`). A context-aware variant (enquiry CTA on private-hire cluster) would align the persistent CTA with page intent. `data-sticky-cta-guard` infrastructure already exists to suppress it near forms.
- **Sunday-roast mixed message (Low)**: hero lead "No booking, no pre-order, just sit down" sits directly above primary CTA "Book a Table" (`app/sunday-roast/page.tsx:145-160`). Both are true (walk-ins welcome; booking recommended for groups/peak) but the juxtaposition invites hesitation. One supporting line under the CTA resolves it: "Walk in, or book ahead for groups and peak times."
